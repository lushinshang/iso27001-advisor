# 📘 使用者操作與使用手冊 (User Manual)
## ISO 27001 Advisor Agent — v1.2.0

歡迎使用 **ISO 27001 Advisor Agent**。本手冊將指引您如何啟動並操作這套系統，為您的資訊安全管理系統 (ISMS) 合規工作提供最佳諮詢。

---

## 1. 系統啟動指南 (Quick Start)

開啟您的終端機（Terminal），切換至專案資料夾後，您可以使用以下兩種方式進行諮詢：

### 方式一：互動 REPL 模式（推薦，適合連續追問）
在命令列輸入：
```bash
python3 main.py
```
啟動後會出現歡迎畫面：
```text
====================================================
🛡️  歡迎使用 ISO 27001 Advisor Agent - 離線顧問系統
  - 本地條文庫已載入
  - 推理後端: Ollama 本地服務 (gemma2)
  - 輸入 'exit' 或 'quit' 可退出系統。
====================================================

💬 請輸入您的 ISO 27001 合規諮詢問題: 
> 
```
您可以直接在提示字元 `> ` 後輸入問題，例如：`如何決定ISMS範圍？`。結束請輸入 `exit` 退出。

### 方式二：單次 CLI 查詢（適合快速查閱）
如果您只想查詢單一問題，可以直接在命令後面加上問題字串：
```bash
python3 main.py "最高管理階層如何展現對資安的承諾？"
```

## 2. 進階參數調用 (Advanced Parameters)

主程式 `main.py` 提供多項參數以配合您的硬體環境與模型偏好：

| 參數 | 作用 | 範例 |
|---|---|---|
| `--model` | 指定本地 Ollama 的模型名稱（預設為 `gemma2`） | `python3 main.py --model gemma4:12b-it-qat-16k` |
| `--top-k` | 每次檢索參考的 ISO 條文數量（預設為 `4`，減小可提升推論速度） | `python3 main.py --top-k 2` |
| `--gemini` | 強制使用雲端 Gemini API 推理（需有 `.env`） | `python3 main.py "如何加密？" --gemini` |
| `--gemini-model` | 指定使用的 Gemini 模型（預設為 `gemini-2.5-pro`） | `--gemini-model gemini-3.1-flash-lite` |

## 3. 解讀顧問解答 (Interpreting Advisor Responses)

當您提出諮詢後，系統會輸出四個部分，這是為了符合專業稽核員的嚴謹回覆邏輯：

```
==================== 📖 ISO 27001 顧問解答 ====================
🎯 [諮詢問題分析]
說明您問題的核心本質與涉及的資安維度。

📖 [依據條文與控制項說明]
精確列出該問題依據的 ISO 27001 條款編號與標準內容。
引用格式一律標註為例如 [A.8.13 資訊備份]，以利翻閱 CNS 標準本。

🛠 [文件缺口與稽核證據建議]
1. 文件缺口：指引您組織內必須制定哪些「書面政策、程序書或管理規範」。
2. 稽核證據：指引您在被稽核時，要提供什麼「運行紀錄、系統設定截圖或簽核紀錄」。

⚠️ [免責與合規警示] (高風險場景)
提示此回覆不具正式認證效力，涉及高風險決策應諮詢 Lead Auditor 最終確認。
==============================================================
```

### 🔍 附註：引用條文依據清單
在回答的最末尾，系統會附帶列出本次推論在資料庫中所參考的條文 ID 與檢索得分（如：`- [control_8.11] 8.11 資料遮罩 (控制措施, 分數: 230.80)`），您可以透過這些 ID 在原始檔 [cht.md](file:///Users/lanss/projects/2_Practice/5-Day%20AI%20Agents%20Intensive%20Course%20with%20Google%282026%29/iso27001-advisor/cht.md) 中做進一步的交叉比對。

## 4. 執行品質評估與 MRR 指標解讀 (Quality Evaluation)

您可以隨時透過執行評估腳本來了解 RAG 系統的檢索品質：
```bash
python3 evaluation.py
```
評估會隨機讀取 `eval_dataset.json` 中的 10 個核心資安諮詢問題，比對檢索輸出並在終端機列印詳細指標：

1. **檢索成功率 (Hit Rate @ 4)**：
   - **含義**：在排名前 4 的檢索結果中，是否**至少包含了一個**我們預期關聯的標準條款。
   - **目前水準**：**100.0%**，代表所有測試情境皆能成功聯想並召回至少一個合規依據。
2. **平均召回率 (Avg Recall @ 4)**：
   - **含義**：所有測試問題中，預期正確條款被成功檢索出來的平均比例（有些問題包含多個預期條文）。
   - **目前水準**：**93.3%**。
3. **平均倒數排名 (MRR @ 4 - Mean Reciprocal Rank)**：
   - **含義**：衡量正確條款被檢索出時的「排序位置」。若第一個結果就是預期正確的條文，得分為 1.0；若在第二個，得分為 0.5。MRR 越接近 1.0，代表最相關的條文被精準排在最前列的機率越高。
   - **目前水準**：**0.9333**。在 RAG 架構中，MRR 的高低直接決定了 LLM 推理時對關鍵條文的聚焦程度，0.9333 代表極高水準的排序品質。
4. **檢索耗時 (Avg Time Per Search)**：
   - **含義**：單次檢索的平均處理時間（以毫秒為單位）。
   - **目前水準**：**0.51 ms**，這得益於 v1.2 引入的 O(1) ID 雜湊映射與類別常數配置。
